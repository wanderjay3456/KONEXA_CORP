# KONEXA 자동 운영 설계와 남은 의사결정

작성일: 2026-09-15. 이 문서는 구현된 기능과 향후 자동화 계획을 구분한다.
완전 무인 채용, 비자 승인, 계약 체결, 정산 보장을 의미하지 않는다.

## 1. 운영 원칙

KONEXA는 기업의 업무 범위와 주차별 결과물을 먼저 정하고, 참여 가능한 인재를 연결해 실제 프로젝트로 검증하는 서비스다.
AI 점수 자체가 상품이 아니라, 확인 가능한 결과물과 운영 품질이 상품이다.

권장 구조는 `이벤트 발생 → 규칙 검증 → AI 초안/비교 → 필요한 사람의 승인 → 실행 → 기록/알림 → 결과 측정`이다.
정상적인 반복 작업은 자동 처리하고, 운영자는 예외·분쟁·신원·최종 적합성을 검토한다.

## 2. 이번에 구현한 기반

| 영역 | 구현 |
| --- | --- |
| 진로 목표 | 실제 프로필 저장, 주당 업무 가능 시간, 재접속 복원 |
| AI 결과 | 분석 시작 전 작업 기록, 성공/실패 상태, 소유자별 이력 조회와 화면 복원 |
| 공급자 오류 | JSON 문법뿐 아니라 필수 내용 검증까지 모델 재시도 안에 포함 |
| 후보 조회 | `is_public=false`인 보호된 인재 디렉터리를 인증된 기업의 서버 요청으로만 조회. 익명 공개로 전환하지 않음 |
| 매칭 | 페이지를 나눠 후보 조회, 주급/시간/근무 방식의 확인된 불일치 제외, 직무 관련 근거로 후보군 축소, 누락 근거 표시 |
| 기업 AI | 공고/매칭 결과가 없어도 업무 범위·주차별 결과물 준비 가능 |
| 알림 | 한 번에 2건씩 잠그되 시간 예산 내 여러 묶음 처리. 장애 시 중단·기존 backoff 유지 |
| 관리자 | 자동 운영 점검 탭: 알림 지연/재시도 한도/AI 실패·미완료/인증 대기 실데이터 집계 |
| 품질 관리 | API 통합 테스트, SQL rollback 검증, 브라우저 저장/복원 테스트와 CI 연결 |

AI 매칭은 채용 결정이 아니다. 언어 숙련도, 미등록 시간/주급, 실제 시작일은 확인 과제로 남긴다.
후보가 10,000명 규모를 넘으면 현재 안전 한도를 조용히 잘라내지 않고 인덱스 기반 검색으로 전환해야 한다.
공개 동의를 철회하거나 정지된 후보는 저장된 기업 매칭 이력에서 다시 표시하지 않는다.

## 3. 단계별 사업 자동화 로드맵 — 아래는 추가 구현 계획

| 단계 | 자동으로 처리할 일 | 사람에게 남길 일 | 완료 기준 |
| --- | --- | --- | --- |
| 기업 유입 | 유입 경로, 동의, 상담 상태 기록; 업종별 소개메일 초안; 중복/수신거부 제외 | 신규 캠페인·대상·발송 승인 | 발송 이력과 수신거부가 재발송을 차단 |
| 기업 요구 정리 | 선택형 업무 템플릿, 필수 질문, 주차별 결과물 초안, 빠진 조건 알림 | 업무 범위와 성공 기준 확정 | 모호한 공고를 그대로 매칭하지 않음 |
| 인재 등록 | 서류 형식/누락 검사, 이력서 추출, 영상 길이 검사, 재제출 안내 | 신원·서류 진위·포트폴리오 검토 | 등록 완료와 검증 승인을 분리 |
| 후보 추천 | 필수 조건 비교, 근거/누락 정보 요약, 후보 명단 버전 관리 | 최초 추천 검수와 최종 선택 | 운영자 평가와 추천 결과를 비교 가능 |
| 면접/프로젝트 준비 | 시간대 변환, 일정 후보, 질문/평가표 초안 | 최종 일정·개인정보 공개·참여 확인 | 중복 일정/무단 연락처 공개 없음 |
| 프로젝트 진행 | 마일스톤 기한 안내, 미제출 감지, 주간 결과물 요약, 변경 요청 추적 | 범위 변경, 품질 판정, 대체 인재 결정 | 완료는 제출/검수 기록을 근거로 표시 |
| 종료/재이용 | 양측 평가 요청, 검증된 경력 기록, 재참여/채용전환 안내 | 분쟁, 보복 리뷰 이의신청, 채용전환 확인 | 승인된 거래만 공개 경력/리뷰에 반영 |
| 운영 감시 | 요청 실패율, 알림 지연, 분석 실패, 오래된 작업 감지 | 예외 처리, 정책/모델 변경 승인 | 실패를 정상/0건으로 감추지 않음 |

영업 메일을 무조건 자동 대량 발송하는 방식은 권장하지 않는다. 동의와 수신거부 처리, 정확한 수신 기업, 실제 제공 가능한 혜택을 먼저 확정한다.
신원 검증/비자/계약/금전 이동을 AI 출력만으로 승인하지 않는다.

## 4. 현재 계정에서 추가 결정이 필요한 사항

1. **상업용 호스팅:** 확인 시 Vercel Hobby. 상업용 서비스에는 Pro/Enterprise 또는 상업 이용이 허용되는 호스팅이 필요하다. 유료 변경은 실행하지 않았다.
   - 공식 정책: https://vercel.com/docs/limits/fair-use-guidelines
2. **알림 정기 복구 주기:** 현재 Vercel Cron은 하루 1회. 즉시 처리와 접속 시 재시도는 별도로 동작한다. 상업용 요금제로 전환한 후 정기 작업을 1~5분 간격으로 운영하고 지연 경보를 연결하는 것이 목표다. 현재 더 짧은 주기로 설정됐다고 주장하지 않는다.
   - 공식 문서: https://vercel.com/docs/cron-jobs
3. **보안:** Supabase 유출 비밀번호 차단은 Pro 이상 기능이다. 자동 심사 경고가 곧 개인정보 유출 증거는 아니다. GraphQL 스키마 가시성과 실제 행 접근 권한은 구분한다.
   - 공식 문서: https://supabase.com/docs/guides/auth/password-security
4. **실제 추천 품질:** 실무자가 적합/부적합과 이유를 표시한 평가 사례가 필요하다. 합성 테스트는 프로그램 검증용이며 실제 채용 성과 근거가 아니다.
5. **정책/비용 확정:** 실제 가능한 서비스 범위, 사람의 검토 책임, 보관 기간, 알림 동의, 취소/분쟁 기준을 확정하고 도움말 3개 언어를 함께 갱신한다.
6. **결제·에스크로·전자서명:** 이번 범위에서 실제 활성화하거나 자금을 이동하지 않았다.

## 5. 측정할 지표와 정의

- 프로필 완료율: 가입자 중 필수 프로필 등록 완료자 비율. 신원 승인율과 분리한다.
- 유효 공고율: 업무 범위·주차별 결과물·연락 정책을 갖춰 게시된 공고 비율.
- 후보 추천 소요 시간: 요청 접수부터 운영자 검토된 후보 제시까지.
- 추천 수락률: 제시된 후보 중 기업이 검토/면접 진행을 선택한 비율. 채용 성공률과 다르다.
- 프로젝트 완료율: 시작한 프로젝트 중 검수 완료한 비율. 취소 사유를 별도 분류한다.
- AI 오류율: 시작 작업 중 실패/기한 내 미완료 비율. 단순 모델 연결 성공률과 분리한다.
- 알림 지연: 다음 처리 가능 시각이 지난 대기 작업의 지연 시간. 수신거부는 실패가 아니다.
- 운영 투입 시간: 기업/프로젝트당 사람의 처리 시간. 자동화 전후 비교한다.

초기에는 소규모 실제 운영에서 문제를 발견하고 기준을 정한 후 자동화 범위를 넓힌다. 운영 규칙이 확정되지 않은 상태에서 업무를 무인화하면 잘못된 결정을 빠르게 반복할 수 있다.

## 6. 장애 대응 순서

1. 관리자 → 자동 운영 점검에서 최근 시각과 경고 수치 확인.
2. 원인 확인 전 무조건 재실행하지 않음. AI 시간 초과는 저장 이력부터 확인.
3. 메일 `failed`는 backoff 대상, `dead_letter`는 운영자 조사 대상, `suppressed`는 수신 설정 존중 결과.
4. 매칭이 비었으면 공고 상태 → 기업 인증 → 인재 프로필/공개 동의/계정 상태 → 근무 조건 순으로 확인.
5. 변경은 테스트 → 미리보기 → CI → 배포 → 운영 상태 확인 순으로 진행.
6. 서비스 제공자 장애를 자체 검증 성공으로 덮지 않으며, 실패율이 높으면 해당 기능의 신규 실행을 제한하고 안내한다.
