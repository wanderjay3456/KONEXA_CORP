# KONEXA 기술 고문 점검 및 안정화 — 2026-09-14

## 이번 변경의 목적

현재 모집·운영 상태와 공개 안내를 맞추고, 가입·로그인에서 발생하는 혼란과 알림 전달 위험을 줄인다. 결제·계약을 실제로 실행하거나 회원 데이터를 삭제하지 않는다.

## 구현한 내용

- 지난 8월 5일 얼리버드는 신규 혜택을 계속 약속하지 않고 현재 초기 파트너 모집 안내로 전환한다. 기존 자격·혜택 데이터는 수정하지 않았다.
- 업무 범위 → 주차별 결과물 → 참여 가능한 인재 매칭을 설명한다. 학생 약 10명은 확보 인원이 아니라 초기 모집 계획으로 명시한다.
- 사용자가 제공한 '모두의 창업 프로젝트 2라운드 진출팀' 소개를 반영한다. 정부 보증이나 자금 수령액으로 확대 해석하지 않는다.
- 예시 프로젝트 카드·리뷰를 실제 실적으로 오인하지 않도록 표시하고, 뒤바뀐 기업·학생 리뷰 관점을 바로잡는다.
- 로그인 창과 이미 번역된 가입 화면을 AI 자동 번역 대상에서 제외한다. 로그인·비밀번호 재설정은 한국어·영어·베트남어 고정 문구를 사용한다.
- 로그인 모달에 제목·입력 라벨 연결, 포커스 유지·복귀, Escape 닫기, 비밀번호 자동완성 정보를 적용한다. 랜딩 제목 CSS가 모달 제목을 크게 만드는 충돌을 수정한다.
- 실제 동작하지 않던 로그인 유지 체크박스를 제거하고 공용 기기 로그아웃 안내로 바꾼다.
- 가입 비밀번호 기준과 안내를 8자로 통일한다. Supabase 서버 설정 자체를 변경한 것은 아니다.
- 학생/기업 프로필을 읽은 뒤 화면 상태를 함께 갱신한다. 상세 프로필이 없는 회원은 미완성 상태로 처리하며, 검증 완료나 경력을 만들어내지 않는다.
- 회원 기본 기록이 없는 인증 계정은 로그인 중 임의 회원 생성으로 우회하지 않는다. 로그인 감사 로그 실패가 로그인 자체의 실패로 표시되지 않게 한다.
- 세션 초기화 실패가 전체 사이트의 무한 로딩으로 이어지지 않게 한다.
- 공고 API 오류와 실제 빈 목록을 구분한다. 12초 조회 제한, 오류 안내, 재시도를 추가한다.
- 익명 DB 쓰기에 의존하던 이메일 소식 폼은 명확한 기업 가입/문의 링크로 교체한다.
- 알림 outbox 작업을 Vercel waitUntil 수명에 연결한다. outbox 재시도 구조와 기존 cron은 유지한다. 성공적인 실제 메일 수신을 증명하는 변경은 아니다.
- 호환 범위의 의존성을 업데이트한다. npm audit에서 확인한 8건(높음 4, 보통 4)을 해결했다.

## 확인한 범위

- 자동 테스트: 기존 6개 + 이번 회귀 테스트 9개 = 15개 통과.
- TypeScript 검사 및 프런트/서버 정식 빌드.
- 브라우저: 3개 언어 로그인 UI, 390px 모바일 화면, 잘못된 계정 로그인 거절, 학생 가입 진입, API 연결 오류 상태.
- 실제 Supabase 계정 생성, 실제 회원정보 수정, 결제, 전자서명, 실제 수신자 대상 메일 발송은 이 검증에서 수행하지 않았다.
- 배포 후 별도로 production 상태와 공개 API 응답을 확인해야 한다.

## 운영 확인 및 다음 우선순위

### P0 — 실제 유료 거래 전에 필요한 결정

1. 국내 PG/에스크로 및 전자서명 공급자 계약·가맹점 심사·콜백 검증. 설정값 존재만으로 거래 가능하다고 판단하지 않는다.
2. 운영자 표시, 개인정보 처리 및 국외이전, 보관·삭제 기간, 실제 처리업체를 반영한 약관·개인정보처리방침 확정. 현재 코드의 문서 요약은 완성된 법률 문서를 대신하지 않는다.
3. Vercel 화면에서 현재 Hobby 요금제가 확인되었다. 공식 안내는 Hobby를 개인 비상업적 용도로 제한한다. 사업 운영을 위한 요금제 전환 또는 적합한 호스팅 선택이 필요하다. 유료 업그레이드는 별도 승인 없이 실행하지 않는다.
   - https://vercel.com/docs/plans/hobby

### P1 — 초기 기업/학생 참여를 받기 전의 운영 검증

1. 별도 테스트 환경과 기업·학생·관리자 테스트 계정을 준비하여 공고 → 지원 → 승인 → 프로젝트 → 결과물 → 상호평가를 한 번 끝까지 검증한다.
2. 앱 내 알림, 이메일, 수신 설정, 실패 재시도, 중복 방지와 실제 메일 도착을 함께 검증한다. 현재 일 1회 cron은 장애 재시도 지연을 만들 수 있으므로 운영 SLA와 예산에 맞춰 조정한다.
3. 기존 app_records와 v2 테이블 소비 경로를 하나씩 정리한다. 테스트 기록은 운영 데이터로 이관하지 않으며 이관 전 백업·건수·소유권·중복 검증이 필요하다.
4. 관리자 승인/미승인, 회사 간 데이터 접근 차단, 비공개 연락처/영상 접근, 첨부파일 검사, 회원 탈퇴·보관 기한을 자동 테스트로 확장한다.
5. 프로필 AI 점수는 채용 결정이 아니라 검토 보조로 표시하고 분석 실패 시 재시도 및 사람이 검토하는 경로를 유지한다.

### P2 — 운영 데이터가 쌓이면

- 초기 JS와 학생 대시보드의 큰 번들을 분리한다. 현재 빌드에는 500kB 초과 경고가 남아 있다.
- 가입 시작/완료, 프로필 완료, 기업 공고 등록, 지원, 실제 매칭 전환을 개인정보 최소 수집 원칙으로 측정한다.
- 대시보드에 남은 실행 시점 AI 번역을 점진적으로 고정 번역 사전으로 교체한다.
- 긴급 오류, 미전달 알림, 운영자 검토 대기 건을 한 관리자 화면에서 우선순위별로 보여준다.

## 변경하지 않은 항목

- 실제 회원·공고·결제·혜택 데이터, Supabase 스키마/RLS, 결제 가격, 사업자 정보.
- 원본 작업 폴더에 있던 홍보 문서·원페이저·robots.txt·sitemap.xml.
- Vercel의 잘못 입력된 것으로 보이는 www.konexa.ac.kr 항목은 소유/사용 여부를 단정할 수 없어 삭제하지 않았다.
